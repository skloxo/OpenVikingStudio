# 断路器与自省停手规则契约 (Circuit Breaker & Reflective Halt Contract)

当触发断路器求证（`force_ask`）或收到包含 `[Antigravity 断路器护栏]` 的提示时，智能体必须严格遵循以下行为规程：

1. **绝对禁止盲目尝试**：
   - 严禁换一个姿势继续无脑调用写文件或执行同类报错命令；
   - 严禁在未经人类确认的情况下强行绕路打补丁。

2. **严禁写长篇文字检讨（防 Token 投毒）**：
   - 严禁输出超过 150 字的心理反思或泛泛而谈的哲学自省；
   - 状态汇报必须极简、脱水、高密度。

3. **收敛为【三行事实 + 双选裁决】向人类交棒**：
   - **现场事实 (Fact)**：一句话说明当前要解决的核心契约，以及导致连续报错的精确物理根因（附关键 Exit Code 或核心报错行）；
   - **已排除假设 (Eliminated)**：说明前几次尝试为何失败，确认哪些方案不可行；
   - **A/B 裁决选项 (Options)**：给出供人类快速决策的两个互斥选项（如：A. 调整底层类型定义 / B. 安装缺失依赖 / C. 降级为只读方案）。

4. **自适应租约与收尾交付心流守则**：
   - **珍惜增量租约**：当人类在断路器弹窗中授权放行后，系统将授予 +15 步增量租约。智能体必须立即收敛至当前核心链路，严禁利用新增租约开启无关的横向发散探索；
   - **交付收尾一气呵成**：核心代码和测试变绿后，立即更新 `REFACTORING_PLAN.md` 与 Git 留痕；系统已针对收尾文档配置豁免通道，智能体应一鼓作气完成闭环，不拖泥带水；
   - **孤儿后台任务即时回收 (Orphan Task Cleanup)**：在执行方案发生切换、或宣布任务达成准备向用户交棒前，必须确认无残留的废弃异步进程。若存在因语法报错、等待或超时而悬挂的孤儿任务，必须立即调用 `manage_task` 的 `kill` 进行彻底回收，严禁在 IDE 侧边栏遗留任何死锁转圈。
