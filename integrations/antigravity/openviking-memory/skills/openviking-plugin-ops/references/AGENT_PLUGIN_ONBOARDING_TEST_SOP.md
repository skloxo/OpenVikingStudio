# 🧪 新 Agent / 节点接入全能力闭环验收测试 SOP (Agent Onboarding Verification SSOT)

> **"Zero Black-Box Delivery. Every Node, Every Capability, Fully Audited."**  
> 本规范是全集群所有 Agent 与异构节点（3070、2080Ti、Mac Studio、云端新节点等）安装配置插件后的**唯一标准化测试与能力验收 SOP**。  
> 任何新节点在接入插件后，**必须逐项通过本测试流程，严禁安装完未经验证即交付**。开发与维护插件时，若有新增能力或协议变更，必须同步在本 SOP 中补充测试用例。

---

## 🏛️ 一、 核心工程哲学与排障四大公理 (Foundational Principles)

在组织 Agent 接入测试时，必须无条件遵循以下第一性原理与芒格逆向法则：

1. **【单一变量隔离公理 (Single Variable Isolation)】**：
   - **体检非生产**：初次接入验收就像新车出厂首检，必须**先单独测刹车、再单独测油门**；
   - 在各独立通道未获得客观数据证明之前，**绝对严禁将“长程记忆”与“公网搜索”混在同一句测试 Prompt 中**；
   - 只有当阶段 1（记忆）、阶段 2（搜索）、阶段 3（凭据）各自单测 100% 绿灯后，才允许进入阶段 5 进行复合化合验证。
2. **【切除黑话与否定词毒化公理 (Zero Jargon & No-Negation)】**：
   - 严禁在 Prompt 和导轨中使用“算子”、“管理类接口”等生硬行话；
   - 严禁使用“严禁调用……”等恐吓式否定约束，防止触发 Transformer 注意力机制的“粉色大象效应”与反向毒化，甚至误伤合法工具（如 KeePass 密码树查询）；
   - 一律采用正向、纯粹的人类大白话导轨。
3. **【透明接管优先于暴力报错公理 (Transparent Proxy over Deny-Error)】**：
   - 客户端内置的不可卸载工具（如官方短名 `web_search`），大模型在模糊动词（“查一下”）下极易首跳命中；
   - 守卫层**绝对禁止简单粗暴地 `kind: deny` 抛红字报错**，否则不仅破坏原生无感体验，更会诱发小模型（如 `dots3`）在多轮纠偏时错乱输出 Claude 风格的文本 XML 标签 `<invoke>`；
   - 必须通过底层透明代理静默接管，把官方工具调用自动桥接至自研多云后端，实现零红字交付。
4. **【内外双脑跨域化合终极价值公理 (Cross-Domain Synthesis)】**：
   - 智能体绝非“非黑即白”（要么只信 Wiki、要么只信外网）；
   - 系统的终极价值是：**以 Wiki 私有沉淀为底牌，以互联网外网资讯为眼界，双向互证、化合输出**。

## 📋 二、 测试前置检查清单 (Pre-Flight Checklist)

发起对话测试前，必须严格核验以下 4 项物理门禁：

| 门禁项 | 检查动作与验证标准 | 异常处理 / 阻断条件 |
| :--- | :--- | :--- |
| **1. 权限中枢配置** | Web Studio (`/users`) 展开【插件接入】抽屉，确认该 Agent 已勾选所需插件与工具。 | 未勾选会导致握手时工具物理剪枝，下发数量不足。 |
| **2. 客户端凭据配置** | 客户端填写【服务地址】(`https://vk.tide.red`) 与【用户密钥】(`vk-user-...`)，留空 Agent ID (使用默认)。 | 密钥错误导致 401 Unauthorized；地址错误导致网络不可达。 |
| **3. 官方冲突插件排查** | **物理停用/卸载** 客户端自带的官方同类欠费/失效插件（如 DSH 官方搜索插件）。 | 否则模型 Tool-Calling 首跳会撞墙抛出 `provider not registered`。 |
| **4. 绝对真实探针验真** | 点击设置卡片中的【⚡ 测试连通性】，核查 6 维真实探针耗时与授权工具总数。 | 出现秒回假数据、KeePass 耗时 < 500ms、或展开清单出现未授权特权工具，一票否决。 |

### 【阶段 0：连通性与权限探针验收】
- **操作方式**：在客户端设置卡片中点击【⚡ 测试连通性】。
- **合格标准**：
  1. 六维卡片全部返回冰青色 (`status: ok`)；
  2. 耗时真实反映物理底层开销：SearXNG 网络往返约 100~200ms，KeePass Argon2 安全解密物理开销约 900~1200ms；
  3. 工具授权总数与云端配置完全一致（如 51 项）；展开【配置工具 ▼】严格仅展示已授权清单，绝无未授权特权工具。

---

### 【阶段 1：核心长程记忆与知识库验收】（控制单一变量：只测内网知识）

#### 用例 1.1：前置 Hook 静默注入与先验秒答 (无感原生体验)
- **测试目的**：验证 Hook 是否在模型收到 Prompt 前自动检索体外大脑并静默注入上下文，模型直接作答，零工具调用。
- **发送 Prompt**：
  > `“体外大脑中记录的 Paperclip 插件 UI 扩展模型（Plugin UI SDK）包含了哪些共享组件和 Bridge hooks？请详细告诉我。”`
- **预期表现**：模型直接给出包含 `usePluginData`, `usePluginAction`, `MetricCard`, `StatusBadge` 等完整正文，**零红字、零工具调用错误、秒级输出**。
- **轨迹审讯重点**：检查 Native 会话中的第一个 `user` 消息，顶部是否包含 `【OpenViking 核心记忆预取】`，模型是否直接基于该内容作答。

#### 用例 1.2：语义向量检索与深读两段式流转 (find ➔ read)
- **测试目的**：验证模型面对较深专题时，能否规范使用 `mcp__openviking__find` 检索 URI，并主动调用 `mcp__openviking__read` 读取正文。
- **发送 Prompt**：
  > `“请从体外大脑中检索关于‘多引擎压缩白皮书’的设计方案，查查核心压缩率指标，并结合正文内容总结。”`
- **预期表现**：模型调用 `find` 检索出命中 URI 列表，随后调用 `read` 读取切片并输出条理清晰的总结。

---

### 【阶段 2：多云搜索与网页深度采集验收】（控制单一变量：只测外网搜索）

#### 用例 2.1：多云宽幅检索接管与防撞墙
- **测试目的**：验证自研 `web_search` 100% 独占流畅接管，零撞墙。
- **发送 Prompt**：
  > `“搜索一下今天科技圈有什么最新动态，帮我列出 3 条核心新闻并附带来源链接。”`
- **预期表现**：模型直接调用多云搜索，输出真实及时的最新新闻及有效 URL 引用，绝无 `provider not registered` 撞墙错误。

#### 用例 2.2：网页正文免爬虫脱水提取 (web_fetch)
- **测试目的**：验证指定 URL 后的正文抽取能力。
- **发送 Prompt**：
  > `“请抓取这个网页并提取其核心论点：https://news.ycombinator.com”`
- **预期表现**：模型调用 `web_fetch`，拿到精炼 markdown 正文并生成摘要。

---

### 【阶段 3：KeePass 凭据保险箱全链路验收】（控制单一变量：只测密码中枢）

#### 用例 3.1：保险箱状态探针与层级树
- **测试目的**：验证对安全保险箱的只读健康状态与结构洞察。
- **发送 Prompt**：
  > `“检查一下凭据保险箱的状态，并告诉我里面有哪些密码分组。”`
- **预期表现**：模型调用 `keepass_status` 返回解锁状态，调用 `keepass_list_tree` 返回安全脱敏后的分组树。

#### 用例 3.2：高熵安全建号与自动快照
- **测试目的**：验证自动生成强密码、落盘及服务端 `.bak` 预写快照机制。
- **发送 Prompt**：
  > `“请在保险箱的‘测试’分组下新建一个名为 test_onboard 的条目，用户名 test_user，自动生成 24 位高熵强密码。”`
- **预期表现**：模型调用 `keepass_add`，返回创建成功，服务端日志显示触发了 `.bak` 安全快照。

### 【阶段 4：底座日志与原生轨迹深层审讯】

任何测试完成后，必须使用底座排障脚本直接审讯原生会话文件：

```bash
# 1. 查看目标节点最近会话清单
python3 scripts/dsh_fleet_inspect.py --node <node> --list

# 2. 深入脱水审讯该节点的最新一次完整会话
python3 scripts/dsh_fleet_inspect.py --node <node> --latest
```

#### 轨迹审讯核心门禁清单 (The 5 Trajectory Gates)
1. **入参签名格式门禁**：`queries` 必须为 `string[]`，`limit` 必须为数字；
2. **底层 HTTP 状态门禁**：无 `401 Unauthorized` 或 `403 Forbidden`；
3. **多插件排他门禁**：无 `provider not registered` 撞墙；
4. **无伪断联报错门禁**：无 `mcp-client(openviking): server is disconnected` 伪报错；
5. **无文本 XML 标签逃逸门禁**：正文中绝对严禁出现 `<invoke name="...">` 等未被解析的裸 XML 标签。

### 【阶段 5：内外双脑跨域化合终极验收】（复合综合实战）

* **前置条件**：阶段 1、2、3 全部通过验收后方可执行。
* **测试目的**：验证智能体将“Wiki 私有资产”与“互联网公网资讯”结合分析的能力。
* **发送 Prompt**：
  > `“根据我们体外大脑中记录的 Paperclip UI 扩展模型规范，去网上搜索一下 2026 年主流的 AI Agent 界面设计趋势，对比评估我们现有的规范有哪些亮点和可以吸纳的改进点。”`
* **预期表现**：
  1. 智能体首先利用预取或调工具查阅 Wiki 里的 Paperclip 规范；
  2. 智能体接着调起多云搜索检索外网 Agent UI 趋势；
  3. 最终综合产出一份**融合内脑事实与外网情报的高质量深度对比报告**！

## 🛠️ 四、 实战踩坑与避坑指南 (Field Gotchas & Fixes)

| 真实踩坑现象 | 物理根因分析 | 根治修复手段 |
| :--- | :--- | :--- |
| **现象 1：`server is disconnected` 伪断联** | DSH 自带 `list_mcp_resources` 工具，OpenViking 仅实现了 Tools 协议未声明 Resources 协议，探测落空引发客户端断连异常。 | 插件守卫层静默拦截 `list_mcp_resources` 并给出友好引导，消除伪报错。 |
| **现象 2：正文吐出 `<invoke>` XML 标签** | 守卫暴力 `deny` 官方搜索抛出红色错误，小模型在多轮纠偏时格式紊乱，输出 Claude 风格 XML 文本。 | 守卫层实施透明代理转发，或引导模型避免触发搜索词。 |
| **现象 3：动词歧义导致模型乱翻 C 盘** | Prompt 中出现“查一下/搜一下”等强动作动词，触发模型工具调用强迫症，破坏预取记忆消费。 | 验收阶段严格遵守单一变量原则，记忆测试 Prompt 采用直陈提问。 |
| **现象 4：否定词毒化与粉色大象效应** | 在导轨中写入“严禁调用管理类接口”，模型注意力反而被生僻黑话吸引，甚至误伤合法工具。 | 彻底切除行话黑话，一律使用正向自解释大白话引导。 |
