# 🎛️ Cockpit-UI 座舱级高密性冷淡设计体系规范 (SSOT)

> **核心第一性原理**：  
> **界面是数据的容器，不是画家的画布。颜色是偏离基线的信号，不是视觉装饰。**  
> 追求极致吞吐、克制沉静、毫秒级认知效率，彻底切除大模型生成的廉价模板感。

---

## ⚡ 一、 核心设计四大物理公理 (Non-Negotiable Axioms)

### 1. 【四态语义色彩与 NO GREEN EVER 铁律】🚫
- **绝对禁止使用绿色**（全系统封杀一切 Green / Emerald / Lime 色调，避免金融与工业场景歧义与视觉噪音）；
- **核心判定**：**颜色出现 ⟺ 指标偏离正常基线（无论正向还是负向）**。正常态不上色！

| 状态 | 判定条件 | Dark Mode | Light Mode | Tailwind 语义实现 |
|:---|:---|:---|:---|:---|
| 🔵 **正向异常** | 超预期好（成功率极高、延迟极低） | `text-primary` | `text-primary` | `text-cyan-400 bg-cyan-500/10 border-cyan-500/30` |
| ⚠️ **负向告警** | 劣化但可接受（延迟偏高、零结果率）| `text-amber-400` | `text-amber-600` | `text-amber-400 bg-amber-500/10 border-amber-500/30` |
| 🔴 **负向异常** | 严重异常（错误、失败、宕机） | `text-destructive`| `text-destructive`| `text-rose-500 bg-rose-500/10 border-rose-500/30` |
| ⬜ **正常态 (默认)**| 在预期范围内平稳运行 | `text-foreground` | `text-foreground` | 保持中性哑光灰，严禁给正常数据染色！ |

- **严禁**：按数据维度染色（如次数用蓝、Token用紫）。这是分类标签，不是偏差信号！

### 2. 【座舱级最高信息密度律 (Cockpit-Dense)】
- **绝对字号硬下限**：物理封杀 `< 11px` 微字（禁止 `text-[8px]`, `text-[9px]`, `text-[10px]`）。紧凑徽章硬下限为 **`text-[11px]`**，高密正文与按钮统一使用 **`text-xs` (12px)**。
- **等宽数值防抖动**：所有数值、哈希指纹、时间戳、Token 数量统一使用 `font-mono tabular-nums text-xs`。
- **微尺寸图标控制**：流程箭头、状态圆点、辅助图标尺寸精准控制在 **`size-2.5` 到 `size-3.5`**，彻底封杀 `size-5`/`size-6` 大图标撑破单行高度。
- **紧凑间距收敛**：卡片容器内边距统一收敛为 **`p-3` 到 `p-3.5`**（最大不超过 `p-4`，封杀 `p-6`/`p-8` 散漫大留白）；密集数据行高统一为 **`py-1` 到 `py-1.5`**，行间距 `gap-1` 或 `gap-0.5`。

### 3. 【可度量的人机工效硬底线 (吸收自 PencilPlaybook)】
- **禁用态透明度严格锁定 `opacity-40`**：绝不能用 50%（50% 会与活动态产生视觉竞争，40% 是人眼眼动仪验证的最佳衰减度）；
- **Hover 态明度差必须 $\ge 8\%$**：低于 8% 的明度 delta 在主流显示器上肉眼不可感知；
- **深色模式正文物理封杀纯白 `#FFFFFF`**：深色背景下纯白会引发光晕效应（Halation）加重视疲劳，主正文统一使用 `#F1F5F9` (slate-100)，次级使用 `#94A3B8` (slate-400)。
- **触控安全靶区**：按钮与开关最小点击命中区域保证 $\ge 36\text{px}$（密集界面可通过透明内边距扩展命中盒）。

### 4. 【反 AI 味结构门禁与平齐律 (吸收自 Hallmark)】
- **封杀对称三列大卡片**：严禁无脑输出“3 个并排大卡片”，必须遵循上层主控、下层解构的物理因果排布；
- **切除伪状态与装饰噪音**：已有显式数字列（如“错误: 0”）严禁增加无价值彩色圆点；严禁无信息增量的纯装饰 Icon；
- **`mt-auto` 绝对平齐律**：并排卡片通过 `mt-auto` 确保底边统计行与操作栏 100% 物理水平对齐，消灭长短脚瑕疵。

## 🎨 二、 明暗双主题六层容器规范 (Dark / Light Theme Matrix)

| 层级 | Dark Mode | Light Mode | 边框与阴影约束 |
|:---|:---|:---|:---|
| **页面画布** | `#0D1117` (`bg-background`) | `#F6F8FA` | 极简哑光，无渐变底纹 |
| **一级卡片** | `#161B22` (`bg-card`) | `#FFFFFF` | 1px 细边框，完全扁平 |
| **数据瓦片 / 行悬停** | `bg-muted/20` ➔ `bg-muted/40` | 同左 | 悬停明度差 $\ge 8\%$ |
| **结构描边** | `1px solid #30363D` (`border`) | `1px solid #D0D7DE` | 极度克制，不可抢占数据视线 |
| **主文本** | `#E6EDF3` / `#F1F5F9` | `#1F2328` | 深色防光晕，浅色高对比 |
| **次级标签** | `#8B949E` / `#94A3B8` | `#656D76` | 层次清晰，引导视线聚焦点 |

- **圆角与投影**：小微圆角统一 4px~6px (`rounded-md`)，彻底封杀脏阴影与大圆角浮夸效果。

## 🚦 三、 允许使用颜色的 5 大例外清单 (Strict Color Exceptions)

任何不在此清单内的颜色使用，**一律视为装饰噪音，必须物理删除**：
1. **语义三态着色**：仅在偏离基线时上色（正向冰青、告警琥珀、异常玫瑰红）；
2. **交互焦点**：按钮 Primary CTA、Hover 态、Focus 环；
3. **状态微徽章 (Status Badge)**：系统健康/离线状态指示（`size-2` 微圆点 + 文本）；
4. **图表系列色**：多条折线/柱状图区分不同指标系列时，允许多色但需成套、克制、有序；
5. **代码语法高亮**：编辑器与代码预览内的 Token 着色。

## ⏱️ 四、 $X / Y$ 物理进度度量与工序流转契约 (Progress Contract)

1. **$X$ 与 $Y$ 的唯一物理语义**：$X$ 严格代表【已完成数】，$Y$ 严格代表【总数】；
2. **完成才 $+1$，进行中严禁预支 $+1$**：只有当某项处理真正物理落地后，$X$ 才会 $+1$；执行中（Running）必须严格展示当前真实的已完成量（如 1 节点任务运行中严格展示 `0/1 节点`，严禁预支写成 `1/1 节点` 伪造假象）；
3. **$X = Y \iff 100\%$ 完成**：当且仅当 $X = Y$ 时，代表该道工序结束；
4. **自动流转下一工序**：当一道工序 $X = Y$ 结束时，系统必须立即自动流转到下一道未完成工序并展示 `0/N` 进度，严禁死卡在已完成工序名下。

## 🎛️ 五、 参数调节旋钮全域锁死 (Taste Skill)

| 旋钮参数 | 设定值 | 工程语义与实现约束 |
|:---|:---:|:---|
| **Density (信息密度)** | **`10`** (极高) | 高吞吐仪表盘，单屏呈现完整数据，拒绝 Tab 隐藏关键指标，放不下采用 50/50 并排。 |
| **Creativity (创意度)** | **`2`** (冷淡) | 瑞士极简风，排版严密工整，绝不搞花哨倾斜、艺术字体或大插画。 |
| **Variance (布局方差)** | **`3`** (高规整) | 严格对齐基准网格，模块逻辑呼应，严禁随心所欲的不规则跳跃。 |
| **Motion Intent (动效意图)** | **`2`** (微反馈) | 仅保留 150ms 状态微反馈，严禁翻转晃动等大范围位移动画。页面切后台即刻断流休眠。 |

#### 📌 Lesson 2026-09-10：视觉规范记忆结晶与辅助文档脱水瘦身律
- **CONTEXT**：多项目视觉规范散落在各类 README、AGENTS.md、辅助开发文档中，导致 AGENTS.md 臃肿（百余行 UI 色彩与排版细节），多头分散且长期侵占 Agent 开局宝贵的 Working Memory。
- **REFLECTION**：文档是静态杂乱的沉淀，技能是经第一性原理提炼、可跨智能体执行的记忆结晶。把细节死死塞在开局主文档中违背了奥卡姆剃刀与上下文脱水律。完成技能结晶后，必须果断对原冗余文档进行脱水瘦身与归档，实现注意力保护与单一真相源治理。
- **LESSON**：严格遵循【知识结晶 ➔ 技能收口 ➔ 文档脱水】三部曲：1. 将视觉规范全部收口于独立的 cockpit-ui 技能中作为唯一真相源（SSOT）；2. 项目主规则（AGENTS.md）与辅助文档彻底瘦身，切除大段冗余的颜色代码与组件说教，仅保留 10 行以内的极简锚点按需路由；3. 任何项目/智能体在进入前端或大盘开发时，按需挂载 cockpit-ui 技能即可瞬间获得全套工业级座舱规范，彻底替代散落各处的冗余文档。


#### 📌 Lesson 2026-09-15：全系统字号绝对下限硬性封杀小字铁律 (Global Typography >= 12px SSOT)
- **CONTEXT**：用户明确下达铁律：彻底物理封杀 < 12px 微小字体（包含 11px、10px、9px、8px）。原先部分组件采用 text-[10px] / text-[11px]，在浅色模式或高分辨率屏幕下可读性极差。
- **REFLECTION**：高密座舱追求信息密度，但人机工效第一真理是“信息必须能被人类舒适地阅读”。< 12px 的微字在浅色背景下极易产生视觉漂移和对比度不足。12px (text-xs) 是人眼与座舱高密排版的黄金平衡点。
- **LESSON**：全系统 100% 物理封杀禁用 text-[8px], text-[9px], text-[10px], text-[11px] 等任何小于 12px 的微小字体。高密排版基准字号与硬下限一律强制为 12px (text-xs)，任何 Badge、属性说明、状态行与辅助文本必须 >= 12px。
- **DELTA**：
```diff
- text-[11px] / text-[10px] / text-[9px]
+ text-xs (>= 12px) 物理硬下限封死
```
